# Sizing

Read once you understand what they want. Pick a size and say it in plain
words. They can override it.

| Size | The full description | Then |
|------|----------------------|------|
| A quick, clear task | the request itself | do it |
| A small change | in chat | build it through the normal workflow |
| A project with a written design | a written design document | a full plan (plan mode after design approval) |

Rules:

- If it grows mid-task, stop, say so, and step up a size.
- If this is really several independent projects, say so, agree on an
  order, and brainstorm them one at a time.
- Quick task: everything material is in the request. Do it, say what you
  did, done.
- Small change: the full description fits in chat. Get explicit approval
  of that in-chat description, then build through the normal workflow.
- Project: anything needing a doc a builder could plan from. Write it
  per [design-doc.md](design-doc.md), run the
  [builder-check.md](builder-check.md), hold the gate, then plan mode.
